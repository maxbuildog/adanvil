# AdAnvil: edit 9:16 video ads through MCP

## 1. What AdAnvil is

- AdAnvil is a deterministic video-ad renderer driven by you. You judge: which footage fits, what the text says, where it sits, whether the result looks right, what to ask the human. AdAnvil executes: cuts, colour, captions, text removal, audio, encoding, checks, contact sheets.
- The same storyboard always gives the same video. If something looks wrong, change the storyboard (footage, timing, text, position), never try to work around the pipeline.
- Everything lives in one project folder (`footage/`, `brand/`, `music/`, `reference/`, `renders/`, `cache/`, plus `adanvil.json`, `brand.yaml`, `catalog.json`). Every tool takes an absolute `project_dir`; every other path is relative to it.
- Tools return images (contact sheets, frames, previews). LOOK at them. Reading only the JSON is how bad ads ship.
- The full doctrine is also available from the `editing_guide` tool, and the JSON Schema from `storyboard_schema`. Use `project_read_text` for small project-relative text files, including licence notes.

## 2. Setup check

Call `recipe_list` first. If it returns nine recipes, the server is connected. If the tool does not exist or errors, tell the human:

- The AdAnvil MCP server is not connected. Install and register it, for example `claude mcp add adanvil -- uvx --from git+https://github.com/maxbuildog/adanvil adanvil-mcp`, or with Docker (`claude mcp add adanvil -- docker run -i --rm -v "$PWD:/projects" adanvil`), or the `.mcpb` extension for Claude Desktop.
- ffmpeg 6.1 or newer must be on the PATH (`ffmpeg -version`).
- Transcription (of the reference, and of the speech in your footage) is optional and needs the `transcribe` extra or `adanvil voice-setup`.

Stop until the server answers. Do not try to emulate it with shell commands.

## 3. The workflow

### Step 1. Project (`project_init`, `project_read_text`)
Pick an absolute folder and a short name. `project_init(project_dir, name)` creates the skeleton and is safe on an existing folder. Tell the human where to drop files: footage in `footage/`, the reference ad in `reference/`, music in `music/`, logo and end card in `brand/`. Use `project_read_text(project_dir, path)` for project-relative `.txt`, `.md`, `.json`, `.yaml`, `.yml` or `.csv` files such as `music/LICENCES.txt`; it returns UTF-8 text and marks truncated output. Later tools refuse paths that escape the project.

### Step 2. Brand (`brand_onboard`, `brand_get`)
Two calls. Call 1: `brand_onboard(project_dir, url="https://...")` with no `answers` reads the site and returns a compact `facts` summary (title, colours, fonts, headings, prices, a few products; `more` counts what it leaves out and the complete facts are saved in `brand/site_facts.json`, read that file only if you need more) plus a `questionnaire`. Ask the human the required questions (brand name, site, niche, hero product, target customer, current offer, guarantee, exact CTA wording, markets, caption language, how to address the viewer, brand voice, banned words, claims guidance, people rules, footage rules, and optionally `product_versions`: how to tell the product versions apart, and `cta_image`: the project path of the brand's ready-made CTA image, if it has one). For emoji, answer `twemoji`, `none`, or a project-relative folder containing the PNG assets; the folder must already exist. Call 2: `brand_onboard(project_dir, answers={...})` writes `brand.yaml` and `brand_brief.md` and returns `open_questions`. Ask again until it is empty.

Never invent an offer, a guarantee, a price or a claim from the site alone: the human confirms them. Read the result with `brand_get` before writing any text; it also returns `emoji_available`, the emoji characters of the brand's emoji folder (`"all"` for twemoji, empty for `none`), so you only use emoji that exist.

### Step 3. Footage (`library_index`, `library_view`, `library_annotate`, `library_search`)
1. `library_index(project_dir, source="footage/subfolder")` catalogs the needed folder (run it on the needed sub-folders rather than waiting for an entire rush library). `source` may be one folder or a single media file. Re-run it after adding files, only new files are processed, and progress is reported per file. Up to 8 new files are indexed in the call; with more, indexing runs as a detached job and the call returns at once with a `job_id`: wait with `job_status(job_id, wait_seconds=90)`, and if the connection drops call `job_status` again (with `project_dir` if it answers "job not found"; jobs survive a server restart). The result is compact: counts, one line per new or updated entry (id, path, duration, people, product_visible, `speech` when the clip speaks), a `speech` count by status and `errors`. Clips with sound are also transcribed (see Talking-head UGC): `transcribe` is `"auto"`, `true` or `false`. Audio files (`.m4a`, `.wav`, `.mp3`, `.aac`) are indexed too, as `audio` entries (no contact sheet, so `library_view` returns their data only) with their duration and speech, and can be used as `audio_from` sources. Index jobs never wait for the project lock, so they run while a voice or render job runs (they only take a short lock on `catalog.json` when saving); several index jobs and annotations can run at once without losing entries. Names with accents are matched whatever their Unicode form on disk (macOS copies), so the catalog path works as written.
2. `library_view(project_dir, entry_id)` for EVERY clip you might use. It returns the entry (duration, HDR flag, shots, text boxes) and a contact sheet. LOOK at the sheet: people, product version, light, burnt-in text, watermarks, what the gesture is.
3. `library_annotate(...)` what you saw: `description`, `tags`, `people`, `product_visible`, `product_version` (a short free string such as `current`, `old` or `v2`; the brand answer `product_versions` says how to tell them apart), `emotion` (a list, a clip can show several: `none`, `neutral`, `worried`, `frustrated`, `sad`, `tired`, `closed`, `skeptical`, `shocked`, `curious`, `relaxed`, `happy`, `satisfied`; what the faces express), `quality` (integer), `usable`, `notes`, `exclude` with `exclude_reason` (competitor footage, watermark, AI before/after, no consent).
4. `library_search(...)` by `text` (annotations, notes, tags, path and what the clips say), `tags`, `people`, `kind`, `min_quality`, `product_visible`, `product_version`, `emotion` (a list), `min_duration` to pick clips without rescanning; results are compact lines like the index summary, and `full=true` returns whole entries. Excluded entries are hidden unless `include_excluded=true`.
4b. **Smart library (optional vision environment).** Run `vision_setup` (or `adanvil vision-setup`) once: about 2.5 GB, CPU only, a small multilingual image and text model (SigLIP 2, Apache-2.0) and a face detector (YuNet, MIT). Afterwards `library_index` also looks at every image and video (`vision` is `"auto"`, `true` to redo, `false` to skip): the frames of the contact sheet are embedded and searched for faces, and each entry gets `auto_tags` (zero-shot labels such as `person`, `bathroom`, `hands`, `smiling`, `text on screen`; they never replace your `tags`, filter them with `auto_tags=[...]`). Then search by SENTENCE across the whole library without opening any sheet: `library_search(query="a woman with a sad face touching her jaw")` (any language) ranks SHOTS and returns the best `limit` (default 12) as lines `#rank | id | path | S<shot> start-end t=<best frame> | score` plus ONE numbered mosaic of their best frames. The usual filters apply first. The score is a centred match probability: 0.5 and more is a clear match, under 0.1 means nothing looks like it. LOOK at the mosaic, then `library_view` the entry before choosing, and rephrase when the answer is off (describe what is SEEN, not the intent). `missing_vision` counts the entries indexed before the environment existed: run `library_index` again. **Product versions: give photos, not words.** In `brand.yaml`, `product_versions: [{name: current, photos: [brand/current-1.jpg, brand/current-2.jpg]}, {name: old, photos: [brand/old-1.jpg]}]` (2 to 5 photos per version: pack, device, label, from several angles, alone or in a hand). Indexing then guesses, per shot that shows the product, the closest version with a confidence (`shots[].product_version`, `product_confidence`, and `auto_product` on the entry); `library_search(product_version="current")` uses the guess when there is no human `product_version` annotation, and a human annotation ALWAYS wins. The guess is a filter to find candidates, not a verdict (it separates different packagings well and small differences on one product badly): confirm on the sheet before using a shot as proof. Without the environment, nothing changes and the index says `vision: unavailable`.
5. For the exact cut frame, `frame_view(project_dir, source, t)` (or `frame=<number>`) returns a full-resolution frame. The contact sheet can be a moment off, so check the frame at your chosen timecode. It returns the frame on screen at `t` (`floor(t * fps)`) and says its exact time (`frame_t`).

### Step 4. Reference (`reference_decode`)
Skip only if there is no reference ad. `reference_decode(project_dir, video="reference/ad.mp4")` returns shots with start, end, text boxes, the soundtrack, per-second loudness, a `music_profile` block (tempo, onset rate and one-word feel of the soundtrack, voice included when the reference speaks), a `pacing` block (shot lengths, cuts per 10 s, per quarter), per shot the spoken words and text regions, the transcript as one string `transcript_text` (`transcribe` is `true`, `false` or `"auto"`, the default: it transcribes when the reference has sound and a transcriber is installed; optional `language`; the per-word transcript and `rms_per_second` stay in `reference.json`, see `files`), the allowed `breakdown_vocabularies` (type, scale, role, motion, emotion), the overview sheet and readable shot sheets (one row per shot, three frames, timing and speech). LOOK at the overview and at EVERY shot sheet, and read the on-screen text of each shot. Add the angle in one sentence, the structure of the text (urgency, secret, reply to a comment, reminder, gratitude, negative bait turned around), WHO SPEAKS in the text (see the next step) and what must be replaced (competitor footage, other brand's product, burnt-in text, logos, watermarks). Text boxes in the result are candidates for `remove_text`.

### Step 4b. Reference breakdown (`reference_breakdown`, `library_overview`)
Fill the `breakdown_template` of the decode and call `reference_breakdown(project_dir, reference, shots)` (`reference` is `reference/<slug>`). For every shot, or run of consecutive shots, set `type`, `scale`, `subject` (`person_a`, `person_b`, `product`, `diagram`: count the distinct people), `on_screen_text` (verbatim), `spoken`, `role`, `motion`, `replacement`, `text_speaker`, `text_device`, `emotion` (`none`, `neutral`, `worried`, `frustrated`, `sad`, `tired`, `closed`, `skeptical`, `shocked`, `curious`, `relaxed`, `happy`, `satisfied`: what the person feels) and `action` (free short text: what the person does, for example "wipes the counter and sighs"). For every reference shot, note what the person feels and does; pick a library shot with the same emotion and the same kind of action. Filter the library with `library_search(emotion=[...])`. Every decoded shot must be covered exactly once; the tool rejects unknown vocabulary and lists the allowed values (they are also in `breakdown_vocabularies` of the decode). **Read who speaks in the text.** `text_speaker` is `none`, `character`, `narrator`, `viewer` or `brand`; `text_device` is `none`, `quote` (a character's words), `punchline`, `question`, `label`, `subtitle_of_speech`, `price_or_offer` or `cta`. An emoji or a name followed by `:` and quotes (for example `😩 : « ... »`) means a character is speaking: mark it `character` + `quote`. The remake must keep the same device (who says what), not just the words, so write those captions as `<emoji> : « ... »` too, not an emoji kept as decoration. The summary counts them in `text_devices` and sets `dialogue` to true when 2 or more entries are character quotes. Read the summary: type demand, scale mix, role sequence, repeated patterns, text devices, `emotion_by_role` (the emotions used for each role) and pacing. Name the repeated pattern (for example `myth > punch`) and the caption hierarchy (for example a small label line with an emoji, then a big punch line), because the remake must keep them. Check the music too: `music_profile(project_dir)` profiles every track of `music/` (tempo, `pulse` = how clearly the attacks stand out, loudness range, feel `calm` (no clear beat), `medium` (a beat under 110 BPM) or `energetic` (a clear beat at 110 BPM or more)), and the decode's `music_profile` gives the reference's. Pick the library track whose profile is closest to the reference's: a calm track under a fast reference feels flat. Then call `library_overview(project_dir)` on the whole footage tree, B-roll folders included (diagrams, close-ups, animations), and look at the mosaics, to find each shot type the reference needs BEFORE choosing shots. Mosaics show 48 files per page: when `pages` is more than 1, call again with `page=2`, `page=3`... (or narrow `path` to a subfolder) until you have seen every file. When a type is missing, take the closest available one or write the replacement as `missing: ...`; do not flatten a fast, varied reference into a few wide shots of one person. Stock and diagram B-roll: footage the brand put in its library is the brand's to use unless the brand rules exclude it; a diagram or 3D animation is the usual replacement for a reference's explanatory shots (anatomy, engine, app architecture). A B-roll or stock shot must show the brand's own category and target (no lipstick shot for a coffee ad, no cat in a dog-food ad, nobody outside the target customer) and say the same thing as its text. A diagram or 3D animation is used only when it is readable in one second (one idea, a recognisable subject, ideally named by the text or voice at the same moment) and the ad explains it; when in doubt, use a real usage shot instead.

**Tell the story in two halves.** The problem part (hook, problem, myth, agitation, and the punch lines that answer a myth) shows the target living the problem: no product on screen, a worried, tired or frustrated face, a runner out of breath, a messy kitchen, the old way of doing things (the long routine, the clunky tool, the expensive alternative). The product appears only when the story turns to the solution (reveal, mechanism, demo), so the viewer first feels the problem, then sees that a solution exists. `storyboard_validate` warns `product_too_early` when a segment before the first solution role shows the product (shot_type product_hero, product_in_use or unboxing, or subject `product`). **Translate each reference shot to the brand's product, never copy its subject:** a mascara ad's eye macro becomes a close-up of the brand's own key detail (the pour for a coffee brand, the sole for a running shoe, the dashboard for an app); another brand's applicator or tool becomes the brand's own gesture. Matching the reference's shot type never justifies a subject outside the brand's category. **Then let the solution breathe:** after the turn, show the result as people live it, several shots of different people using the product and looking happy and relaxed, with a visible sign of the result (a calm face, a tidy kitchen, an easy run), before the offer. One product-only shot is not a payoff.

**Remaking a reference**: set `reference` in the storyboard to `reference/<slug>` (the folder of the breakdown) and annotate EVERY segment with `shot_type`, `scale` and `subject`, using the breakdown vocabularies, plus `role` and, on every person shot, `emotion`. `storyboard_validate` then compares your edit with the reference and returns `ref_*` warnings plus a `reference_comparison` block (mean shot, type coverage, close-up share, people, captions). Treat them as creative feedback to fix, not to silence. A type listed in `gaps` (`[{"type": "diagram", "reason": "..."}]`) needs a real reason: it is not in the library after `library_overview` of the whole footage tree.

Tools (43): `project_init`, `project_read_text`, `brand_onboard`, `brand_get`, `library_index`, `library_view`, `library_annotate`, `library_search`, `speech_view`, `speech_takes`, `speech_refine`, `library_overview`, `reference_decode`, `reference_breakdown`, `frame_view`, `recipe_list`, `recipe_get`, `editing_guide`, `storyboard_schema`, `storyboard_save`, `storyboard_patch`, `caption_preview`, `end_card`, `storyboard_validate`, `render_start`, `voice_generate`, `voice_view`, `music_profile`, `music_search`, `music_fetch`, `music_generate`, `music_beats`, `sfx_list`, `storyboard_snap`, `job_status`, `qc_run`, `ad_score`, `compare_pair`, `vision_setup`, `variants_build`, `render_batch`, `render_formats`, `timeline_export`.

### Step 5. Compliance questions, BEFORE editing
Put these to the human in ONE message and keep the answers in a short decision log next to the storyboard (for example `decisions.md`):
- Claims in the reference (voice and text): which may this brand make? Anything on age, body, health, money or income, "cure" or "guaranteed result" wording, or before/after promises needs an explicit answer.
- Before/after: same person, same framing and light, unretouched, not AI generated, obtained with this product?
- Third-party marks: logos, competitor names, other brands' products, watermarks.
- Foreign currency or prices that do not fit the brand's market or offer.
- Press or endorsement mentions: confirmed and sourced?
- Written consent for paid advertising from every customer, creator or public figure shown.
- Provenance: an ad from an ad library belongs to an advertiser, not to a customer.
- Licence of the reference music or voice.
- Numbers ("Day 30", "in 5 weeks") come from the human, never from timestamps in the video.
If the human overrules a reservation, propose compliant alternatives once, then execute and record it. Do not reopen it.

### Step 6. Recipe (`recipe_list`, `recipe_get`)
Nine recipes: `before_after`, `customer_diary`, `hook_plus_product`, `meme_text`, `remake_long`, `text_hook`, `comment_reply`, `voiceover_ad`, `ugc_talking`. Map the reference to one:
- short before/after with an authentic pair: `before_after`
- real customer phone diary with consent: `customer_diary`
- reference opening is compliant and worth keeping untouched, then product: `hook_plus_product`
- one joke or "POV" line over one creator, 18 to 26 s: `meme_text`
- long voiced ad (35 to 60 s) whose script works, rebuilt after the opening: `remake_long`
- voiceless hook sentence over a demo with a trending sound, 14 to 22 s: `text_hook`
- voice-over series answering a real comment: `comment_reply`
- brand narrator voice over usage shots, 22 to 42 s (a spoken reference rebuilt without a fake testimonial, or an idea from scratch): `voiceover_ad`
- a creator talking to camera (several takes per line), their own voice kept, B-roll laid over it, 18 to 45 s: `ugc_talking`
`recipe_get(recipe_id)` returns `when_to_use`, duration range, caption style, the `structure` (slots with `role`, `purpose`, count, shot duration, footage, caption, effects), `rules` and the `checklist`. A slot's `role` is the value for the `role` of its segments: the `result` slot of `ugc_talking` is a `payoff` and the `end_card` slot a `cta`. The checklist is your acceptance test at QC time. The `example` storyboard is a working shape to copy. If no recipe fits, say so and adapt the closest one, keeping its rules.

### Voice-over (optional, any recipe)
AdAnvil generates a French or English (and 20+ other languages) voice-over with Chatterbox, an open-source TTS that runs in its own Python environment: the human runs `adanvil voice-setup` once (downloads about 3 GB of models on first use). Generation runs on CPU: about 25 to 35 seconds per line on an idle 8-core server (9 lines in about 5.5 minutes), several times slower on a busy machine. Two engines: `chatterbox` clones a reference voice (the default and the recommended voice for ads: the owner listened to both engines and kept it; slow); `kokoro` (`adanvil voice-setup --engine kokoro`, spec `{"engine": "kokoro", "voice": "ff_siwis"}` with no `reference`) uses fixed French or English voices, about 4 times faster end to end: use it for drafts and previews (script, timing, captions), then generate the final voice with chatterbox.
1. Write the script: 6 to 10 short sentences, one idea each. The voice speaks **in the name of the brand** (a narrator), never as a fake customer. Use a reference voice the brand has the right to use (about 10 s of clean speech, e.g. `voices/narrator.mp3`).
2. `voice_generate(project_dir, name, spec)` with `spec = {"engine": "chatterbox", "reference": "voices/narrator.mp3", "language": "en", "lines": [...]}` (`language` is optional: when it is absent the `language` of `brand.yaml` is used, else `en`; set it when the script is not in the brand's language) starts a detached background job. Jobs keep running if the MCP session ends. Wait with `job_status(job_id, wait_seconds=90)` again and again instead of polling in a tight loop (some MCP clients cut a tool call after about 2 minutes, so keep each wait under that); progress reports TTS lines done and an ETA. Each line is generated, trimmed to its words and checked by transcription.
3. `voice_view(project_dir, name)` returns every line with `start`, `duration`, `status` and `transcript`, plus suggested segment boundaries. A `suspect` line was misread: change only that line's wording and call `voice_generate` again with the whole script, under the same name (it replaces that voice; the job summary says `replaced: true`) or a new one; unchanged lines come back from the cache in seconds, only the edited line is generated again (an agent cannot listen; trust the transcript). Each line also carries `unmatched_words`: expected words of 4+ letters that the transcript does not contain (close spellings and hyphen or elision merges count as heard). One unmatched word is only reported (often a brand name the transcriber spells differently: check the transcript); two or more make the line `suspect` even when the similarity is high: reword those words (or replace the brand name with a simpler spelling in `say`) and regenerate.
4. Build the timeline from those durations: one shot per sentence (two when a sentence lasts more than about 3 s), the last segment (end card) lasting the last line plus about 1.5 s of music.
5. In the storyboard: `"audio": {"voice": "voice/<name>/manifest.json", "voice_offset": 0, "music": "music/track.mp3", "music_volume": 0.35}` (music under the voice). The bed is first brought to a reference level (-11 LUFS, plain gain, bounded to -12 / +15 dB), then `music_volume` applies: 0.32 to 0.38 sits about 5 dB under the voice whatever the track, so the value no longer depends on how loud the file is. Pick a track whose energy matches the reference, with `music_profile` (a soft piano under a fast edit feels flat) and captions synced to the voice with `{"type": "voice_captions", "mode": "chunks", "max_words": 3, "case": "upper", "style": "outline", "y": 1290, "size": 56}` (`mode: "sentence"` for one caption per sentence; `lines: [0, 1, ...]` to caption only some lines). Captions show the script text, timed on the spoken words. A line may be `{"say": "forty-nine dollars ninety", "show": "$49.90"}` when the voice must say something other than what the captions display; the pronunciation check ignores numbers and currency words in French and English, so "49 dollars" heard for "forty-nine dollars" is not flagged. When the end card already shows the call to action as text, leave the last sentence out of `lines` so the same words do not appear twice. Check chunk captions with `caption_preview` (it accepts a `voice_captions` overlay and a `chunk_index`; a `speech_captions` overlay too, with `chunk_index` and optionally `storyboard`). Chunks never run across the end of a sentence and stop at a comma once they hold two words. Add `animation` for the look viewers expect on social ads (see Animated captions in step 8).
6. Validation adds `voice_cut` (the video ends before the voice: error), `voice_tail` (less than 1 s of music after the last sentence) and `voice_suspect`.

### Talking-head UGC (optional, recipe `ugc_talking`)
A creator talking to camera is the most common paid-social ad, and the speech is already in the footage: index it, choose the best takes, cut on the pauses and keep the creator's own sound.
1. **Index with speech.** `library_index` also transcribes, with word timestamps, the clips that have an audio stream, in the same job: `transcribe` is `"auto"` by default (clips with sound that is not near-silent), `true` forces every clip with an audio stream, `false` does no speech work. It uses faster-whisper when it is installed, else the voice environment (`adanvil voice-setup`); with neither, entries get a speech status `unavailable: ...` and indexing still succeeds, so install one and run `library_index` again (only the missing speech is done, nothing is re-measured). The model is `ADANVIL_SPEECH_MODEL` (default `base`: fast and good enough to search what the clips say, but about one key word per line can be misheard), the language is the brand's `language`, else auto-detected, and the brand name, the product name and the optional `speech.vocabulary` list of `brand.yaml` (names, rare terms) are given to the transcriber as its initial prompt. Each entry carries `speech` (`status`, `language`, `text`, `has_speech`) and `library_search(text=...)` finds what a clip says; the timed words are in `cache/speech/`. One model load per job; the speech of each file is saved as soon as that file is done, so `library_search(text=...)` already works while the job runs (stage `transcribing`). Audio files (`.m4a`, `.wav`, `.mp3`, `.aac`) are indexed the same way, as `audio` entries. A video whose sound track is silent gets the speech status `silent_audio` (not `done` with an invented language) and, when audio files of the same or a nearby folder share words with its name, `separate_audio_candidates` (for example `HOOK1.mov` and `VOIX OFF/HOOK1.1.m4a`): the voice was probably recorded apart. AdAnvil does not sync separate sound: lay the audio file on a segment with `audio_from` and check the sync on a preview before going on.
2. **Choose the takes.** `speech_takes(project_dir, source="footage/hooks")` (or `entry_ids`) groups the phrases of several files that say the same line (`HOOK1.mov`, `HOOK1.1.mov`, `HOOK1.2.mov`) and returns, for each line, the best take with `why` and its `clean_segments`; `others` lists what put the other takes behind (a filler, a restart, a cut ending, a speech rate or a level out of the natural range). Then **refine the words of the takes you keep**: `speech_refine(project_dir, sources=[...], model="medium")` (`sources` are project paths of clips, a folder, or entry ids) starts a detached job that transcribes those clips again with a stronger model and the brand vocabulary and replaces their words in place (wait with `job_status(job_id, wait_seconds=90)`; the result is `refine`; a clip that fails keeps its old words). A medium model needs about 2 GB of memory and is several times slower than the indexing model, so run it on the chosen clips, not on the whole library. Do it before the next step, so that the cuts and the captions use the right words; `speech_view` reports the `model` of the words.
3. **Cut on the pauses.** `speech_view(project_dir, entry_id | source, max_pause=0.35)` returns the compact `phrases` (`start`, `end`, `text`, `flags`: `restart` when the next phrase repeats it, `filler` when it holds a hesitation, `uncertain` when the transcriber doubted a word, so check it or refine; per-word data only with `words=true`; at most `max_phrases` (60) per call, `first_phrase` and the `note` page through a longer clip), the `fillers` (euh, heu, hum, bah, ben, um, uh, er everywhere; genre, du coup, like only when said alone between pauses; replace the lists in `brand.yaml` under `speech.fillers` and `speech.isolated_fillers`), the `restarts` (a phrase repeated by the next one: a retake inside one file; `drop_restarts=true` also cuts them out) and `clean_segments`: ready-to-paste `{source, in, out}` clip segments that keep the speech and drop the pauses over `max_pause` and the fillers, with 0.06 s kept before and 0.10 s after each stretch, never cutting inside a word. Paste them as segments and add `label`, `focus` and the rest.
4. **Keep the creator's own sound.** `"audio": {"clips": true, "music": "music/track.m4a", "music_volume": 0.25}`: the bed is the original audio of the clip segments, exactly aligned with the picture (a 10 ms crossfade at each cut), brought to `voice_loudness` (-15 LUFS) on its own, with the music under it like under a voice-over. An image, a clip without audio and a frozen hold are silence, so keep the music running under the end card (QC flags a silent tail). `clips` excludes `voice` and `from_reference`.
5. **B-roll over the voice.** A clip segment with `"audio_from": {"source": "footage/creator.mov", "in": 7.24}` shows its own picture and plays the sound of that clip from `in` for the length of the segment (an L-cut: the creator keeps talking over a product shot). Take `in` from the clean segment where the sentence goes on. It needs `audio.clips`.
6. **Captions from the speech.** `{"type": "speech_captions", "mode": "chunks", "max_words": 3, "case": "upper", "style": "outline", "y": 1290, "size": 56}` builds the captions from the words of every played range (jump cuts, `speed` and `audio_from` taken into account) and leaves hesitations out unless `keep_fillers` is true. It needs `audio.clips`. A word that is still misheard after `speech_refine` can be shown right with `"corrections": {"heard": "shown"}` (applied word by word, ignoring case, punctuation kept): each correction must be a close spelling of the heard word (character similarity of at least 0.5, `rites` to `rides`), else it is an error asking you to transcribe the clip again, and `storyboard_validate` lists every correction in a `speech_corrections` warning for a human to review. Never use it to put words in the speaker's mouth. Check one chunk with `caption_preview` (the overlay with `chunk_index`, and `storyboard` so the timeline is the one of your ad).
7. **Validation** adds the warnings `cut_mid_word` (a cut of the sound falls inside a spoken word: move it into the pause; no warning when the next segment resumes the same source within one frame, because the voice goes on) and `banned_word_spoken` (the creator says a banned word of the brand: cut it out or pick another take), plus `speech_missing` (a clip with sound has no transcript, so those checks and its captions cannot see it), `speech_corrections` (the corrections of a `speech_captions` overlay, to review), `caption_on_end_card` (a caption stays more than 0.2 s on the end card image: end it before the card) and `cta_text_missing` (the brand's CTA wording is in no caption: add it as a caption on the end, unless your end card image already shows it) and the errors `speech_captions` (the overlay needs `audio.clips`) and `audio_from` (no `audio.clips`, or its source has no sound or too little of it).

### Music (find or make a track, with its licence)
1. **Search.** `music_search(project_dir, query, mood, min_duration, max_duration, source, limit)` searches Openverse (no key) and, with `FREESOUND_API_KEY` set, Freesound (`source="freesound"` or `"all"`). Only licences that allow commercial use and modification are listed: CC0, PDM, CC BY, CC BY-SA (NC and ND are dropped). Each track has its licence, author, duration, `preview_url` and `attribution_required`.
2. **Fit it to the ad.** `fit_to="storyboard"` with `storyboard="storyboards/<name>.json"` ranks the tracks that are at least as long as the ad first, then the feel guessed from the title and tags (`audio.music_feel`: calm, medium or energetic, or the `feel` argument). Without a fitting track, a shorter one loops with a crossfade.
3. **Fetch.** `music_fetch(project_dir, source, id)` saves the track in `music/` with `<file>.licence.json` and a line in `music/LICENCES.txt`, then returns tempo, feel and loudness measured on the real file (`music_profile`). Compare the feel with the ad's before choosing.
4. **Licence in the render.** The render report (`music`) and `ad_score` (`facts.audio.music_licence`) carry the licence. A track with no record raises `music_licence_unknown`: check its licence by hand or fetch it again. A CC BY or CC BY-SA track raises `music_attribution_required` with the exact text: paste it in the ad's description. The batch manifest has a `music licence` column.
5. **Make one locally** (optional). `adanvil music-setup` installs ACE-Step (Apache-2.0 code and weights); `music_generate(project_dir, prompt, duration)` queues a job (minutes on a CPU), poll `job_status`. No attribution is needed. It needs about 20 GB of free memory (18 GB peak measured for 30 s on a CPU) and is refused below that (`ADANVIL_MUSIC_MIN_FREE_GB`); prompt fidelity is weak (tempo and feel often differ from the prompt), so check `music_profile` and prefer `music_search`.

### Sound design (optional, any recipe)
Sounds make a fast text ad feel finished: a whoosh on a cut, a pop when a caption appears, a ding on the price, a riser before the reveal, and cuts that land on the beat of the music. Voice, clips and music stay the bed; sounds are laid over it.

1. **Build the pack once per project.** `sfx_list(project_dir, fetch=true)` (command line: `adanvil sfx-fetch <project_dir>`) puts about 18 short sounds in `sfx/`: `whoosh_short`, `whoosh_long`, `swoosh`, `swipe`, `pop`, `click`, `tap`, `ding`, `chime`, `notification`, `cash_register`, `camera_shutter`, `record_scratch`, `typing`, `riser_1s`, `riser_2s`, `impact`, `boom`. Each one is downloaded from a pinned CC0 source (checked by SHA-1) or synthesised in code (`generated`; a download that fails is synthesised instead, and `offline=true` synthesises all of them), then trimmed and set to one level: its loudest 400 ms at -16 LUFS, its peak under -1.5 dBFS. The source and licence of every sound are in `sfx/LICENCES.txt` (and `examples/sfx/README.md`); nothing is stored in the repository. Files you drop in `sfx/` yourself work the same way. `sfx_list` shows what is there, with durations.
2. **Place a sound** with an `sfx` overlay: `{"type": "sfx", "source": "sfx/whoosh_short.wav", "at": 3.2, "volume": 0.8}` (`source` may also be a bare name such as `whoosh_short`; `at` is seconds on the final timeline). It is mixed over the finished bed after the bed's loudness is set, with a limiter that keeps the peak under -1.5 dBFS (the true peak of the render stays under -1 dB), and it never runs past the end. It works with every audio mode (music only, voice, clips, or none). Volume 1.0 is about the level of a voice, so 0.4 to 0.6 sits under speech. A riser stops at its peak: place it so its end meets the reveal (`at` = the reveal time minus 1 or 2).
3. **Or let AdAnvil place them**: `"audio": {"sfx_auto": {"cuts": "whoosh_short", "captions": "pop", "every": 1, "min_gap": 0.6, "volume": 0.5}}`. A sound goes at each cut between segments (one cut in `every`) and at the start of each written caption (`caption` overlays only, not the captions generated from a voice or from speech); a sound that would fall within `min_gap` seconds of one already placed is skipped (cut sounds are placed first). `sfx_auto` is expanded to explicit sounds, listed in `summary.sfx` of `storyboard_validate` and in the `storyboard_save` result, so you see where they land and can add an explicit `sfx` overlay or change `every` and `min_gap`.
4. **How many.** Use sounds on fast text ads, reveals and offers. A sound on every cut gets tiring: put one on every second cut (`every: 2`) or only on the key moments (the reveal, the price, the end card) with explicit overlays. One kind of sound per role: a short whoosh for cuts, a pop for captions, a ding or chime for a price or result, an impact or a riser for the reveal. Keep them under a voice (volume 0.3 to 0.6) and never stack three at once. Leave sounds out of a calm testimonial or a creator talking to camera: the voice is the sound.
5. **Cuts on the beat**, for a music-led ad. `music_beats(project_dir, path, start)` returns the beat times of a track as it will play (`start` is `audio.start`; times are seconds from the start of the ad). `storyboard_snap(project_dir, storyboard, to="beats", max_shift=0.2)` moves each cut that lies within `max_shift` seconds of a beat onto it: the `out` of the earlier clip (or the `duration` of an image) changes, `in` points and the order of segments never do, no segment becomes shorter than 0.5 s, the other cuts and the total duration stay, and the written captions, images and sounds that started on a moved cut move with it. With `audio.clips` the cuts of talking segments never move. The result lists the `moves` and the cuts `kept` with the reason; `save_as` saves it as a new storyboard with its own `name` (the `save_as` name) and `output.path` (`renders/<save_as>.mp4`, quality kept); without `save_as` the returned storyboard is named `<name>_snapped` with the matching output path, so rendering it never overwrites the original. When music is set, `storyboard_validate` returns an info `beat_alignment` (how many cuts are on a beat, within one frame). A track without a steady beat (a piano, a pad) has no beats and nothing to snap to.
6. **Validation** adds the errors `sfx_missing` (the sound is not in the project: run `adanvil sfx-fetch`), `sfx_not_audio` and `sfx_after_end`, and the warning `sfx_auto_empty` (`sfx_auto` names no sound).

### Visual devices (optional, any recipe)
An ad can use a few visual devices beyond plain cuts. Each one has a job; use **one or two per ad**, never all of them: too many devices make an ad look cheap and hide the product.

1. **Split screen** (`split` segment): two pictures playing together, to show an honest before/after, a problem and its solution, or two products. `{"type": "split", "layout": "side_by_side" | "top_bottom", "duration": 3, "panels": [panel, panel], "gap": 8, "gap_color": "#000000", "labels": ["FROM THIS", "TO THIS"], "label_style": "label" | "pill" | "outline"}`. A panel is `{source, in, focus, crop, speed, freeze, gamma}` for a clip (it plays from `in` for `duration`; a clip that ends sooner holds its last frame) or `{source, fit}` for an image (`fit` `cover` by default, `contain` keeps the whole picture on a blurred background). Each panel is cover-cropped to its half around `focus`, so pick the layout from the footage: portrait clips suit `side_by_side` (each half keeps about half the width), landscape clips `top_bottom`. `labels` are two short texts (one per panel, `null` for none) drawn near the top of each half. The segment is a normal mezzanine with an exact frame count, works in every recipe, and `annotation` fields (`label`, `role`, `shot_type`...) are as for a clip. In the `before_after` recipe it is the second choice, after `reveal`, for a side by side comparison of two real pictures (same person, same framing, same light, unretouched, confirmed). The two panels must be two different takes: when both come from the same file at overlapping moments the validation warns `split_same_source`.
2. **Video inset / picture-in-picture** (`video` overlay): a clip played inside the frame on top of the segments, for example a creator reacting over a screenshot of a product page or a review, or a close-up of the product in a corner. `{"type": "video", "source": "footage/creator.mp4", "in": 4.0, "start": 0.5, "end": 4.5, "x": 660, "y": 1180, "width": 340, "shape": "rect" | "rounded" | "circle", "border": {"width": 8, "color": "#FFFFFF"}, "shadow": true, "audio": false}`. `x`, `y` and `width` describe the whole inset, border included; the height follows the clip (give `height` to force it; a circle is square). Without `end` it lasts as long as the clip from `in`. It is silent by default; `audio: true` needs `audio.clips: true` and replaces the sound of the bed under the inset (refused when a voice-over or another voice is active). Keep it out of the faces and the captions of the shot below it.
3. **Stickers and arrows** (`sticker` overlay): `kind` is `arrow` (`from` and `to`, or the tip at `x`, `y` with `direction` and `length`), `circle` (hand-drawn, centred on `x`, `y`, `width`, `height`), `underline` (from `x`, `y`, `width`), `badge` (a rounded rectangle with `text` such as "NEW" or "-20%", top-left at `x`, `y`, `size`; `x: "center"` or `anchor: "center"` centres it across the frame, any sticker but an image without `width`), `emoji` (`emoji`, `x`, `y`, `size`) or `image` (`source`, `x`, `y`, `width`). `color` defaults to the brand highlight colour (yellow if unset), except for a `badge`: the brand's `visual.accent_color`, else a neutral dark `#111827`, with white text; `animation` is `none`, `pop` (a quick scale-in with an overshoot) or `draw` (arrow, circle and underline drawn over 300 ms). Use them to point at one detail (a price, a feature, a review score), never to decorate. Measure the position on a `frame_view` of the shot below.
4. **Progress bar** (`progress` overlay): `{"type": "progress", "position": "top" | "bottom", "height": 8, "color": "#FFD400", "background": "#FFFFFF55"}` fills from left to right across the whole ad (or from `start` to `end`) and is full on the last frame. It helps on longer ads (more than 25 s) to keep the viewer through the middle; on a 15 s ad it is noise.
5. **Punch-in** (`punch` on a clip segment): `"punch": [{"at": 1.2, "zoom": 1.15, "hold": 0.5, "center": [540, 760]}]`. At `at` seconds into the segment the picture jumps (no ramp) to `zoom` for `hold` seconds, then jumps back, centred on `center` (output pixels) or, without it, on the segment's `focus`. Use it on the strongest word of a talking head, once or twice in a shot, with a zoom between 1.1 and 1.25: a punch above 1.25 counts as digital zoom (`digital_zoom` warning). Punches in one segment must not overlap.
6. **Reveal** (`reveal` segment; with the vision environment its faces line up by themselves, see `align_faces` below): a full-frame before picture that a divider line sweeps away to show the after picture. `{"type": "reveal", "duration": 3.4, "before": {"source": "footage/kitchen_before.jpg"}, "after": {"source": "footage/kitchen_after.jpg"}, "direction": "left_to_right" | "right_to_left" | "top_to_bottom", "hold_before": 0.8, "sweep": 0.9, "focus": [0.5, 0.4], "labels": ["BEFORE", "AFTER"], "label_style": "label" | "pill" | "outline", "divider": {"width": 6, "color": "#FFFFFF", "shadow": true}, "motion": "static" | "zoom_in", "back_and_forth": false}`. Each side is a clip (`in`, `focus`, `crop`, `speed`, `gamma`: both clips play together from their own `in`, so a person moves on both sides) or a still image (`fit`; `crop`, `{x, y, w, h}` in source pixels, keeps one part of it, so one half of a brand's side-by-side composite is a side with no file prepared), cover-cropped to the frame; a segment `focus` is used for both sides so faces and the product line up (a side's own `focus` is used when there is none). **Face-aware framing** (vision environment): `focus: "face"` on a clip, an image, a split panel, a reveal side or the reveal itself keeps the main face centred across and `face_y` of the way down (default 0.38), from the boxes stored at indexing (or a detection made on the spot); for a clip the crop follows the face, smoothed over time. A reveal does more by default (`align_faces: true`): when both sides show exactly ONE face, both faces are put at the same place AND at the same size (the smaller face is enlarged to the bigger one, up to 1.6x), so the divider crosses one face that changes instead of two that jump; set `align_faces: false` to keep your own `focus`. A picture with two faces, or no detector, is cropped as before. A `contain` image has nothing to crop, so `focus` does nothing there. The before side shows alone for `hold_before`, the divider crosses the frame in `sweep` seconds (eased: slow, fast, slow) and the after side stays until `duration`; `hold_before + sweep` must fit in `duration`, and under 0.6 s of after picture warns `reveal_after_short`. `labels` (before, after) follow their side: the before label disappears as the divider passes it and the after label shows up with the after picture. `divider: null` is a plain wipe, `motion: zoom_in` zooms both sides together (up to `zoom_to`, 1.04 by default), and `back_and_forth: true` makes the sweep go across, back to the middle and across again (a slider being dragged) inside `sweep` (give it 1.6 s or more). It is a normal mezzanine with an exact frame count, `annotation` fields (`label`, `role`, `shot_type`...) are as for a clip. See Before and after.
7. **Picture card** (`image` overlay with `animation`, `frame` and `rotate`): a photo or a screenshot that comes in over the video as a card. `{"type": "image", "source": "footage/photo_pair.jpg", "start": 4.0, "end": 7.0, "x": 90, "y": 560, "width": 900, "animation": "pop" | "slide_left" | "slide_right" | "slide_up" | "fade" | "none", "exit": false, "frame": {"radius": 36, "border_width": 12, "border_color": "#FFFFFF", "shadow": true}, "rotate": -3}`. The entry lasts 250 ms: `pop` scales in with a small overshoot, `slide_left` comes in from the right moving left, `slide_right` from the left, `slide_up` from below, `fade` fades in; `exit: true` plays it backwards over the last 250 ms. `frame` rounds the corners (`radius`), draws a border and a shadow; `x`, `y` and `width` then describe the whole card, border included. `rotate` turns it by a few degrees (positive is clockwise) for a photo card look. Without these fields an image overlay is the plain picture it always was. Every animation state is its own cached picture, so the render is the same every time. Keep the card out of the faces and the captions of the shot below it.

Look at every device on a frame (`qc_run` crops each inset and shows one frame of each split screen, and two of each reveal: mid-sweep and after). Validation: errors `split_layout`, `panel_crop`, `source_duration`, `inset_out_of_frame`, `inset_audio`, `sticker_out_of_frame`, `sticker_render`; warnings `split_crop` (a panel keeps under 40% of its source), `digital_zoom`, `text_overflow` (a label wider than its panel), `caption_covered_by_inset` (a caption hidden under an inset while both are on screen), `inset_source_short`, `inset_audio_replaces`, `inset_audio_silent`; for reveals and before/after pairs, the warnings `split_same_source`, `reveal_orientation`, `reveal_after_short`.

### Before and after (optional, recipe `before_after`)
A before/after is the strongest proof in a paid ad when the two pictures are real and the difference can be seen at a glance, and the weakest when they are not. Three devices carry one: `reveal`, `split` and a picture card (see Visual devices). Use ONE of them per ad.
- **Two real pictures.** The same person, the same framing and distance, the same light and time of day, unretouched, not generated or enhanced by AI, obtained with this product, with the written consent of the person for paid advertising. The human confirms each point before editing (Step 5); you never decide it from the pictures. Never present an AI or retouched picture as a real result, never invent the interval ("after 30 days": it comes from the human), and never show a before/after the brand cannot back up. If the human has no real pair, say so and use a recipe without one.
- **A difference you can see.** Two crops of the same take show nothing: the validation warns `split_same_source` when the two sides are one file at overlapping moments (two different moments of one long clip are fine). Look at the frame at mid-sweep (`qc_run` returns it, `frame_view` shows any instant): if you cannot tell the two sides apart in one glance, the pair is wrong, not the effect. Keep both sides in one orientation family (`reveal_orientation` warns when one is portrait and the other landscape), because both are cropped to the same frame, and set one `focus` on the face or the product so the two line up.
- **Choose the pair with `compare_pair`, and LOOK.** Before writing the segment, compare EVERY available pair: the photos, the brand's side-by-side composites split with `crop` (`before_crop` and `after_crop`, `{x, y, w, h}` in source pixels: a reveal side takes the same `crop` on an image, so the composite needs no preparing) and frames of before/after clips (`before_t`, `after_t`). `compare_pair(project_dir, before, after)` returns `visible_difference` from 0 to 100 (under 12 not visible, under 30 subtle, under 55 visible, 55 and over obvious), measured on the face when a skin-region heuristic finds one in both pictures, else on the whole frame after aligning sizes, and a side-by-side preview image. Look at every preview and use the pair whose difference is obvious at a glance: a pair that scores low looks the same to the viewer. Still images of the same pose beat moving clips for a reveal. The score ranks, your eyes decide, and the human confirms the pair (Step 5).
- **Which device.** `reveal` first: the viewer watches the change happen, which is the point of a before/after (a still pair or two clips, `left_to_right` as the default, `top_to_bottom` for a standing person or a surface, `back_and_forth` for a slider look). `split` for a side by side comparison that the viewer should study for longer (two products, two methods, a result shown next to its starting point). A **picture card** (an `image` overlay with `animation`, `frame` and `rotate`) when the proof is a quick one inside another shot: a customer's photo pair or a review screenshot that comes in over a talking-head ad for 2 to 3 s and leaves with `exit: true` while the creator keeps talking. Do not stack them.
- **Timing and text.** With the defaults a reveal needs 3 to 3.5 s: 0.8 s on the before so it is understood, a 0.9 s sweep, then 1 s or more on the after (under 0.6 s warns `reveal_after_short`). Labels are two short words in the language of the ad, never a claim ("AFTER", not "CURED").
- **Compliance.** The caption describes the picture, not a promise: no medical outcome, no "guaranteed result", no result for everyone (add the brand's own "results vary" wording when it has one). Written consent and the confirmation of the pair go in the decision log. If the human overrules a reservation, propose a compliant alternative once, then execute and record it.

### Step 7. Write the storyboard
Write it as JSON (object in the tool call, or a file under the project such as `storyboard.json`). Compact annotated example:
```json
{
  "version": 1,
  "name": "brand_hook_v1",
  "recipe": "text_hook",
  "segments": [
    {"type": "clip", "source": "footage/a.mp4", "in": 3.0, "out": 5.4, "focus": [0.5, 0.45], "label": "usage:1"},
    {"type": "clip", "source": "footage/b.mp4", "in": 12.2, "out": 14.0, "zoom": {"from": 1.0, "to": 1.04}, "label": "product:1"},
    {"type": "clip", "source": "footage/c.mp4", "in": 0.0, "out": 4.4, "label": "end_card"}
  ],
  "overlays": [
    {"type": "caption", "style": "outline", "lines": ["Gentle reminder that you", "deserve a slower morning"], "start": 0.0, "end": 4.2, "y": 330, "size": 62},
    {"type": "caption", "style": "box", "lines": ["Guarantee line", "Tap Learn more"], "start": 5.0, "end": 8.6, "y": 1280, "size": 46}
  ],
  "audio": {"from_reference": "reference/ad.mp4", "volume": 0.9, "fade_out": 1.0},
  "output": {"path": "renders/brand_hook_v1.mp4", "quality": "final"}
}
```
Rules for writing it:
- **Labels come from the recipe slots**: `slot` or `slot:n` (`usage:1`, `product:2`, `end_card`). Recipe rules match on the label prefix, so a wrong label silently skips the duration checks.
- **Roles come from the recipe slots too**: set the `role` of each segment from the `role` of its slot as `recipe_get` shows it (the `result` slot is a `payoff`), never from the slot name: `result` is not an accepted `role`.
- **Time maths**: a clip lasts `(out - in) / speed + freeze.hold`; an image lasts `duration`. The timeline is the sum, in order. Compute every segment start and end before placing overlays.
- **Overlay times are on the final timeline** (seconds from the start of the whole ad), not inside a clip. `end: null` means to the end of the video. Keep a caption on screen about 3 s.
- Paths are relative to the project, forward slashes. `in`, `out`, `source` are required on clips.
- **remove_text**: take the box `[x0, y0, x1, y1]` from the `text_boxes` of `reference_decode` or `library_view`, in source display pixels. Use `mask` for fixed text, `delogo` for a measured box, `crop_out` when the text sits near the top or bottom edge. Place the new caption so it covers at least the erased area. A bright background is not text: boxes over 60 % of the frame area, or over 90 % of both its width and height, and boxes seen on fewer than 2 sampled frames are left out of `text_boxes`.
- One hook only, adapted from the reference structure. Do not rewrite it from scratch.
- **Send the storyboard once (remote servers).** A storyboard is easily 8 KB and the loop is write, preview, validate, fix, render. Call `storyboard_save(project_dir, storyboard, name)` once: it writes `storyboards/<name>.json` in the project and returns the path. Then pass that path (`"storyboards/<name>.json"`) as `storyboard` to `storyboard_validate`, `render_start` and `caption_preview` instead of the object. For a small edit call `storyboard_patch(project_dir, name, changes)` with `changes` a list of `{"path": "segments.3.out", "value": 4.2}` (dot or index paths, `segments[3].out` works too; a key that does not exist yet is added, the index just past the end of a list or `-` appends, `{"path": "overlays.1", "remove": true}` deletes). The changes apply together or not at all, the file is rewritten and the result lists the schema `problems` left. A change of `name` also moves `output.path` when it was the default of the old name (`renders/<old>.mp4`); a path set by hand stays. Keep the saved file as the single source of truth: patch it rather than sending a second copy.
- **Reproduce the caption hierarchy of the reference**, not only its words: for example a small label line with an emoji at the top plus a big punch line in the middle, alternating, with the same size ratio and position. Measure them on the reference frames.

### Step 8. Caption placement (`caption_preview`)
For EVERY captioned shot call `caption_preview(project_dir, source, t, overlay)` with the real source file, a time inside the shot and the exact overlay object. It returns `bbox`, `size_used`, `overflow`, final `lines` and an image (for `voice_captions`, the resulting captions are listed once in `expanded`). For a `voice_captions` overlay pass `manifest`: the `audio.voice` path of your storyboard (`voice/<name>/manifest.json`). Pass `emoji` (same values as the storyboard `emoji` field) so the preview uses the project emoji set; `emoji_missing` lists emoji without a PNG in the folder. LOOK at the image. The text must never cover a face, eyes, mouth or the product being used. If it does, move it (top y 70 to 330 when the top is free, bottom y 1250 to 1500 when the face is high) or shrink it (cartouche 42 px, bubble 32 px, fewer lines). If `overflow` is true or `size_used` fell well below the requested size, cut the line instead of letting it shrink under about 50 px on a main text.

**Animated captions.** Add `animation` to a `caption`, `voice_captions` or `speech_captions` overlay (default `none`, nothing changes):
- `karaoke`: the whole chunk stays on screen and the word being spoken is lit. Use it for captions that follow speech (`voice_captions`, `speech_captions`, 2 to 4 words a chunk).
- `word`: one or two big words at a time (30% larger than `size`; a word of up to three letters is shown with the next one), the spoken one lit. Use it for punchy hooks and short key lines.
- `pop`: each chunk scales in from 85% to 100% in 120 ms with an ease-out (`bounce: true` overshoots to 108% over 180 ms). Use it for written captions, where no word is spoken one by one. Emoji are part of the chunk and pop in with it.
- The lit word is drawn in `highlight` (a colour; default the brand's `visual.highlight_color`, else yellow `#FFD400`), optionally `highlight_scale` times larger (1.1 to 1.2 reads well) and on a rounded `highlight_box` colour (with a box and no `highlight`, the word turns black or white to stay readable). Pick a highlight that contrasts with the text and the shot.
- A plain `caption` with `karaoke` or `word` spreads its words evenly between `start` and `end`; pass `word_times` (`[start, end]` for each word, on the timeline) when you know them. `voice_captions` and `speech_captions` use the real word times.
- The text never moves from one state to the next, and an animated render costs about the same as a static one.
- **Keyword emphasis**, with or without an animation: `emphasis: ["word", ...]` draws those words in the highlight colour (case and accents ignored). In a typed caption, or in the `show` text of a voice line, `*word*` does the same: `{"say": "forty nine dollars", "show": "only *$49* today"}` (the voice never says the stars). Emphasise the one word that sells, two at most per chunk. Numbers and prices work: `"65,90 €"`, `"65,90"`, `"65.90€"` and `"-20%"` match the price however it is spaced, a multi-word entry (`"livraison offerte"`) matches those consecutive words, and `*65,90 €*` or `*-20%*` mark any text, spaces included; the stars are never drawn. `storyboard_validate` and `caption_preview` warn `emphasis_unmatched` when an entry matches nothing in its caption.
- Check where the highlight lands: give the overlay `chunk_index` and `word_index` (the lit word of that chunk), or leave them out to get the state on screen at timeline time `t`. The result names the `word_index`, the `window` of the state and the number of `states`. For a `pop`, `t` inside the first 120 ms of the chunk shows a frame of the scale-in. Pass `storyboard` (a saved path or the object) so a `speech_captions` preview uses the timeline of your ad.

### End card (`end_card`)
**Brand CTA image first.** When the brand has a ready-made call-to-action image (`brand.cta_image`, for example in a `cta/` folder or `brand/`), use it as the last segment (`image`, `motion: zoom_in`, about 3 s, label `end_card`), as the brand made it; `storyboard_validate` warns `cta_image_unused` otherwise. When the human confirmed that image, end on it even if you have doubts (an old product version, a discount that does not match the offer, unverified press logos): the brand decides its own assets; write your doubts in the delivery notes instead of replacing it. Compose an `end_card` only when there is none, or when the human has not confirmed an image that you find outdated (then say why in `gaps`, type `other`, and label the last segment `end_card`). To compose one instead of ending on a bare product shot: `end_card(project_dir, spec, name)` writes `brand/endcards/<name>.png` (1080x1920, or the `spec.format` size) and returns the path, the layout boxes (`pill`, `title`, `photo_card`, `subline`, `badges`, `button`, `title_lines`, `photo_scale`) and the image. LOOK at it: balanced spacing, nothing near the edges, text centred, the photo is the product as sold today. The same from a terminal: `adanvil end-card SPEC.json --project DIR --name NAME`.
- Feed it real material only: a product photo (or a video with `t`, plus an optional `crop` {x, y, w, h} in the source's display pixels, before scaling: on a 1920x1080 frame `{"x": 600, "y": 100, "w": 700, "h": 700}` keeps a 700 px square; the tool returns `source_size` [w, h] to measure it) checked for the current version, the real offer (`pill`, `title`), the real guarantee and rating (`badges`, up to 3) and the brand's exact call-to-action wording (`button`). Never invent a term, a rating or a price; check them against the landing page.
- Spec: `product_image`, `pill`, `title` (a string, or runs `[{"text": "Your first box is ", "accent": false}, {"text": "free", "accent": true}]`), `subline`, `badges` (`{"text", "icon": "check" | "star" | "none"}`), `button` (`{"text", "arrow": "down" | "right" | "none"}`), colours `accent`, `text`, `muted`, `background` (two colours), `family` (default `poppins`), `emoji`. Colours default to `brand.yaml` (accent, else `#2563EB`). A banned word of the brand on any text is an error. Long titles wrap to two lines and shrink to fit; the photo is fitted inside its card and never upscaled beyond 1.25x.
- Put it last: `{"type": "image", "source": "brand/endcards/<name>.png", "duration": 3.0, "motion": "zoom_in", "background": "blur", "label": "end_card"}`, after the last caption, with no subtitle or caption on it. With a voice-over it lasts the last line plus 1.5 s.

### Step 9. Validate (`storyboard_validate`)
`storyboard_validate(project_dir, storyboard, recipe_id)` (`storyboard` is the object or a saved path, see step 7). The rules of the recipe named in the storyboard's `recipe` field are applied here and again by `render_start`, so always set `recipe`. Fix every error. Each warning is a question: fix it or be able to say why the ad is better with it. A rule with severity fail is a blocker. Iterate until `ok` is true, then read the `summary` (total duration, checklist). `score_check=true` also runs the cheap half of the creative score as `score_*` warnings (see Before delivery: score the ad).

### Step 10. Preview render (`render_start`, `job_status`)
`render_start(project_dir, storyboard, quality="preview")` returns `{job_id, status: "queued"}`. If the storyboard is invalid it returns `status: "rejected"` with the errors and creates no job: fix and call again. Jobs are detached and keep running if the MCP session ends or the server restarts; use `job_status(job_id, wait_seconds=90)` repeatedly to wait (pass `project_dir` if it says "job not found") (keep each wait under about 2 minutes, some MCP clients cut longer tool calls). A done job returns the report and a contact sheet image. Previews are 540x960 and are written next to the final path with a `.preview` suffix (`renders/name.preview.mp4`), so they never overwrite a delivered final. Their report is also distinct: `renders/name.preview.report.json`; final renders use `renders/name.report.json`.

### Step 11. QC (`qc_run`)
`qc_run(project_dir, video, render_report=job_id)` returns technical checks, the sheet, `end.jpg` and up to four overlay crops (first, last and two evenly spaced). LOOK at every image: text readable, not cut, off faces, product version correct, no colour jumps, burnt-in text gone at three instants, end card steady, the story reads without sound. Go through the recipe checklist line by line. Fix and re-render: only changed segments are rebuilt, the cache makes it fast.

### Before delivery: score the ad
`qc_run` says the file is correct; `ad_score(project_dir, video, storyboard)` says whether the ad is any good. Run it on the final-quality render with the storyboard it was rendered from (the object or its saved path), LOOK at `safe_zones_preview.jpg` and at the frame of each top finding, fix the findings by impact (each has a `time`, a `severity` and a `fix`), render again and aim for 80 or more. Its cheap half runs earlier: `storyboard_validate(..., score_check=true)` adds the checks that need no pixels as warnings prefixed `score_` (`score_reading_time`, `score_reading_long_line`, `score_product_too_early`, `score_product_never_shown`, `score_cta_missing`, `score_cta_wording`, `score_cta_not_at_end`, `score_safe_zone`) and lists what passed and what it skipped in `summary.score_precheck`.

The score mixes six sub-scores, each from 100 down by its findings (weights in brackets): hook (20), pacing (15), reading (20), story (20), safe_zones (10), audio (15). Every threshold is a guideline, not a rule: a finding is a question, so fix it or be able to say why the ad is better without the fix.
- **Hook** (first 1.5 s): a cut or motion in the first second, a face or the product (from the segment annotations, else a skin heuristic), a written text within 0.5 s, audio from the first half second (`hook_static`, `hook_no_subject`, `hook_no_text`, `hook_silent_start`).
- **Pacing**: cuts per 10 s by quarter, the longest shot, a shot over 4 s in the middle of a fast ad (shots of 2.5 s or less on average: `pacing_dip`), a shot over 6 s (`long_shot`), a slow ad (`pacing_slow`).
- **Reading**: a written caption stays on screen 0.25 s per word + 0.6 s, at least 1.2 s (`reading_time`); at most 7 words per line (`reading_long_line`); a contrast of 3:1 or more between the text and the pixels around its letters on the real frames, a WCAG-like luminance ratio (`reading_contrast`, high under 2:1).
- **Story**: no product before the story turns to the solution (`product_too_early`), the product shown at least once (`product_never_shown`), the call to action written or spoken (`cta_missing`; `cta_wording` when the brand's own `cta_text` is not the one used), an end card or the call to action in the last 4 s (`cta_not_at_end`).
- **Safe zones**: a caption, comment, badge, emoji or image sticker, or a picture overlay, inside the interface that `tiktok`, `reels` or `stories` draw over an ad (`safe_zone`; `platforms` limits the check). The preview draws the zones of each platform over a mid-ad frame and outlines the overlays, red where one falls inside.
- **Audio**: integrated loudness from -20 to -10 LUFS (outside -24 to -9 is a high finding), the voice at least 4.5 dB above the music (`voice_masked`: the default `music_volume` 0.35 leaves about 5 dB and passes; above 0.4 the voice starts to drown), no silence of 0.7 s or more (`audio_silence`).

Without the storyboard the score still runs on the pixels and the sound; the checks that need words, timings or roles are listed in `skipped` and left out of the mix.

Platform safe zones, as pixel boxes (left, top, right, bottom) on a 1080x1920 frame (they scale with the frame size): the top bar is the app header, the right-side button column holds like, comment and share, the bottom band holds the account, the description and the call to action button. A box counts as inside when it overlaps a zone by 24 px or more in both directions. Stories have no button column.
- `tiktok` `top_bar` (0, 0, 1080, 150), `tiktok` `right_buttons` (900, 760, 1080, 1480), `tiktok` `bottom_band` (0, 1480, 1080, 1920)
- `reels` `top_bar` (0, 0, 1080, 250), `reels` `right_buttons` (940, 1000, 1080, 1580), `reels` `bottom_band` (0, 1580, 1080, 1920)
- `stories` `top_bar` (0, 0, 1080, 250), `stories` `bottom_band` (0, 1580, 1080, 1920)
- `feed` `top_bar` (0, 0, 1080, 100), `feed` `bottom_band` (0, 1780, 1080, 1920): the placement of 4:5 and 1:1 renders, scaled to the frame height; `ad_score` picks it by itself for such a video

### Step 12. Final render and delivery
`render_start(..., quality="final")`, poll, `qc_run` and `ad_score` again (80 or more), LOOK again. Deliver a complete video, not a storyboard in words. Tell the human: the file path, which recipe and why, duration, footage used, every open compliance point (unconfirmed claim, licence, consent, offer to check against the landing page). Keep earlier versions (`previous/v1`), change only what they ask, and write generalising feedback into the project's learnings file with the date. Do not rename or file final assets until they approve.

### Step 13. Test variants and formats (when the ad will run as an A/B test)
Vary the HOOK first (the first 2 to 3 seconds), keep everything else identical: `variants_build(project_dir, base, {"hook": [{id, changes}, ...], "cta": [...]})` makes the matrix (3 hooks x 1 body x 2 CTAs is a common start, 24 at most; a change is a `storyboard_patch` list or a slot replacement `{replace_label: "hook", segments, overlays}` that shifts everything after it, refused when a voice-over would no longer match), saves each variant and returns a contact sheet of their first 3 s and last 3 s (the CTA shows): LOOK at it. `changes: []` is the control; sounds (`sfx`) after a slot move with it; every error comes back at once. `render_batch(project_dir, storyboards, formats=["9:16", "4:5", "1:1"])` renders them all in one job with a shared segment cache and writes `renders/<batch>/manifest.csv` (file, variant ids, format, duration, score, hook text, CTA text) for the ads manager. `render_formats(project_dir, storyboard)` is one storyboard in the three formats (`<name>_9x16.mp4`, `_4x5.mp4`, `_1x1.mp4`): LOOK at each (a cropped face or a caption on the product needs a hand-made version). The guide's section 11 has the details.

## 4. Storyboard cheat-sheet

Top level: `version` (1), `name` (letters, digits, `_ . -`, max 80), `recipe`, `reference` (folder or `breakdown.json` of a reference breakdown: turns on the `ref_*` checks), `gaps` (`[{type, reason}]`: reference shot types you could not cover, `type` from the breakdown vocabulary), `format` (`width` 1080, `height` 1920, `fps` 30), `formats` (optional `["9:16", "4:5", "1:1"]`, used by `render_formats` and `render_batch`), `emoji` (`twemoji`, `none` or a project folder), `segments` (at least 1), `overlays`, `audio`, `output`. Unknown fields are rejected.

Clip segment (`type: "clip"`):
- `source`, `in`, `out` (seconds in the source), `label`
- `shot_type`, `scale`, `subject`: annotate the segment with the breakdown vocabularies (`shot_type` = the breakdown `type`, `scale`, free `subject`, `person_*` for people); also valid on image segments; `role` (a breakdown role) and `emotion` (what the face expresses) annotate a segment the same way and feed `emotion_mismatch`
- `focus` [fx, fy] in 0..1: where to keep the crop when cover-scaling to 9:16 (default centre)
- `crop` {x, y, w, h} in source display pixels, applied before scaling. It is for removing edges or burnt-in text, up to about 1.25x. Never crop a medium shot to fake a close-up: it looks zoomed and soft. Close-ups come from footage filmed close (`storyboard_validate` warns `digital_zoom` above 1.25x, counting `crop`, `zoom.to` and `freeze.zoom`)
- `speed` 0.25 to 4 (default 1)
- `gamma` `"auto"` (default, lifts dark shots), a number, or `null`
- `zoom` {from, to, focus}: slow zoom, product shots 1.00 to 1.04
- `freeze` {hold, zoom, center}: freezes the LAST frame for `hold` s while zooming towards `center` (output pixels). To freeze mid-shot, end the segment there.
- `audio_from` {source, in}: with `audio.clips`, the segment shows its own picture and plays the sound of `source` from `in` for its duration (B-roll over the creator's voice)
- `punch` [{at, zoom (1.15), hold (0.5), center}]: instant zooms inside the segment, no ramp, centred on `center` (output pixels) or `focus`; no overlap; counts for `digital_zoom` only above 1.25
- `remove_text` {method, box, extra_boxes, threshold, dilate, blur}: `box` is required; `method` is `mask` (fixed text, pixel mask, blur only inside it), `delogo` (measured box) or `crop_out` (keep the band above or below the text)

Image segment (`type: "image"`): `source`, `duration`, `motion` (`static` or `zoom_in`), `zoom_to` (1.04), `background` (`blur` or `#RRGGBB`), `fit` (`contain` or `cover`), `crop` (`{x, y, w, h}` in source pixels, kept before anything else, so one half of a side-by-side composite can be used; one that leaves the picture is a `panel_crop` error), `label`. Use `zoom_in` for an end card image only (`zoom_to` 1.00 to 1.06: the zoom is sub-pixel, so a still never trembles). A still in the middle of a video must be `static` unless a smooth zoom adds something.

Split segment (`type: "split"`): `layout` (`side_by_side` or `top_bottom`), `duration`, `panels` (exactly two: a clip `{source, in, focus, crop, speed, gamma, freeze: {hold, zoom, center}}` or an image `{source, fit, crop}`), `gap` (8), `gap_color` (`#000000`), `labels` (two texts or `null`), `label_style` (`label`, `pill`, `outline`), and the annotation fields `label`, `shot_type`, `scale`, `subject`, `emotion`, `role`. See Visual devices.

Reveal segment (`type: "reveal"`): `duration`, `before` and `after` (each a clip `{source, in, focus, crop, speed, gamma, freeze}` or an image `{source, fit, crop}`), `direction` (`left_to_right`, `right_to_left` or `top_to_bottom`), `hold_before` (0.8), `sweep` (0.9), `back_and_forth` (false), `focus` (one crop focus for both sides), `labels` (two texts or `null`), `label_style`, `divider` (`{width: 6, color: "#FFFFFF", shadow: true}` or `null`), `motion` (`static` or `zoom_in`), `zoom_to` (1.04), and the annotation fields `label`, `shot_type`, `scale`, `subject`, `emotion`, `role`. `hold_before + sweep` must fit in `duration`. See Visual devices and Before and after.

Overlays (all: `start`, `end`, `null` end = end of video):
- `caption`: `style`, `lines` (list, one string per line), `y` (default 330), `anchor` (`top` or `bottom`), `x_center`, `size`, `family`, `weight`, `fg`, `stroke`, `box`, `accent`, `max_width` (960), `uniform_width`, and the animation fields below (`animation`, `highlight`, `highlight_scale`, `highlight_box`, `bounce`, `emphasis`, `word_times`). Text never renders wider than 960 px. `*word*` in `lines` marks an emphasised word.
- `comment`: `text`, `look` (`facebook` or `tiktok`), `header`, `meta`, `reactions`, `y`, `x_center`, `size`. Real comment only, real count, no invented author.
- `image`: `source`, `x`, `y`, `width`, for badges and insets (top-left corner position); as a picture card also `animation` (`none`, `pop`, `slide_left`, `slide_right`, `slide_up`, `fade`), `exit` (false), `frame` (`{radius, border_width, border_color, shadow}`) and `rotate` (degrees, positive is clockwise). See Visual devices.
- `voice_captions`: captions generated from a voice-over manifest (see Voice-over): `mode`, `max_words`, `lines`, `case`, `style`, `y`, `size` and the animation fields.
- `speech_captions`: captions generated from the speech of the clips on the timeline (needs `audio.clips`): `mode` (`sentence` or `chunks`), `max_words`, `case`, `keep_fillers` (false), `corrections` (`{heard: shown}`, close spellings only, see Talking-head UGC), `style`, `y`, `anchor`, `size`, `family`, `weight`, `fg`, `stroke`, `box`, `max_width`, and the animation fields. No `start`, `end` or text: they come from the speech.
- `sfx`: a sound over the audio bed (see Sound design): `source` (a file of the project or a bare name of `sfx/`), `at` (seconds on the final timeline), `volume` (0 to 2, default 0.8). It has no `start` or `end`.
- `video`: a clip inset (picture-in-picture): `source`, `in`, `start`, `end` (none: as long as the clip), `x`, `y`, `width` (the whole inset, border included), `height` (optional), `shape` (`rect`, `rounded`, `circle`), `radius`, `border` {width, color}, `shadow`, `audio` (false; true needs `audio.clips`). See Visual devices.
- `sticker`: `kind` (`arrow`, `circle`, `underline`, `badge`, `emoji`, `image`), `start`, `end`, `animation` (`none`, `pop`, `draw`), `color`, and per kind `from`/`to` or `x`/`y`/`direction`/`length`/`stroke`, `width`/`height`, `text`/`size`/`fg`, `emoji`, `source`.
- `progress`: `position` (`top`, `bottom`), `height` (8), `color`, `background`, `start`, `end`: a bar filling across the ad.
- Animation fields (`caption`, `voice_captions`, `speech_captions`): `animation` (`none`, `karaoke`, `word`, `pop`; default `none`), `highlight` (colour), `highlight_scale` (0.5 to 2, default 1), `highlight_box` (colour), `bounce` (pop only), `emphasis` (list of words). See Animated captions in step 8.

The 7 text styles. The validated main styles are `outline` (native social text over moving shots) and `pill` (calm shots); `box` is for offers and calls to action, `label` only a small tag:
- `pill`: one white rounded pill per line, black text. Calm shots, brand-voice captions.
- `outline`: heavy white text, black stroke, no box. Native social hook over moving shots, and large stamps.
- `outline_soft`: medium white text, strong outline and shadow. Customer diaries and phone footage.
- `box`: dark rounded cartouche, white text, centred on the visual middle of the text. Offers, prices and calls to action, on a product end shot.
- `meme`: one long text balanced into short centred lines. Single-text meme ads (about 52 px, y about 1290, five lines).
- `label`: small clean tag, a white rounded card with dark text and a soft shadow (the `accent` field is ignored). A small tag or callout only, never the main text.
- `comment`: the comment overlay bubble. One real reply-to-comment hook.

Effects: zoom (above), freeze (above), `remove_text` (above). Hard cuts only, no transitions.

Audio: `music` (file in `music/`) or `from_reference` (soundtrack of a reference or diary video), never both. With `clips: true` the bed is instead the original sound of the clip segments (see Talking-head UGC), normalised to `voice_loudness` with `music` under it at `music_volume`; it excludes `voice` and `from_reference`. `start`, `volume` (default 0.8), `fade_in` (0.2), `fade_out` (1.0). Music shorter than the video loops with a crossfade, longer is trimmed, audio always ends with the video. `loudness` is the integrated target of the final bed, default -14 LUFS (`null` keeps the source level). No audio source means silence, which QC flags unless intended. With a voice-over, `voice`, `voice_offset`, `music_volume` and `voice_loudness` (-15 LUFS) apply instead: see the Voice-over step. `music_volume` (0.2 to 0.6, default 0.35) applies after the bed is brought to -11 LUFS (plain gain), so 0.32 to 0.38 sits about 5 dB under the voice whatever the track. `sfx_auto` ({`cuts`, `captions`, `every`, `min_gap`, `volume`}) places sounds at the cuts and at the written captions (see Sound design).

Output: `path` (default `renders/{name}.mp4`), `quality` (`preview` 540x960 fast, or `final`). The contract is H.264, yuv420p, bt709, 30 fps, AAC 48 kHz. HDR phone clips are tone-mapped for you, do not pre-convert.

## 5. Rules that are easy to forget

- Product-only shots last 1.6 to 2.0 s and never under 1 s. Usage shots 2 to 2.5 s, before/after shots 2 to 3 s, hands-only inserts 0.6 to 0.8 s (about 3 s total).
- A caption stays on screen about 3 s. Long text is split in two beats, never one block. Sentence case by default, all caps only for key words, stamps or a house style the brand asks for.
- One strong hook, adapted from the reference structure. No variants inside one video.
- One person per video when that person speaks on camera or the text says "I". A narrator voice-over (the brand speaking, "tu"/"you" to the viewer) is a general text: vary people like the reference does (`ref_people`).
- The CTA is always last: the brand's own CTA image (3 s, slow zoom; compose one with `end_card` only when the brand has none or it is out of date) or a product shot of about 4.4 s with a `box` text.
- The product appears exactly as sold today in every product-only shot. Check each one on the contact sheet.
- Real comments only, never invented. Real customer words only, quoted as such.
- Claims describe what the product is, does and feels like, in terms the brand can prove ("small-batch roasted", "ready in five minutes"), never a medical outcome, a cure, a guaranteed result or a named competitor. The banned words list is a floor, not a review.
- Guarantee, price and offer use the brand's real terms and match the landing page. Never invent terms.
- Cut hard in the middle of the useful gesture. Never show the same shot twice. Prefer bright, well-lit shots.
- Text never covers a face, eyes, mouth or the product in use.
- Never leave silence at the end of the audio.
- Sounds are for fast text ads, reveals and offers; never on every cut of a calm or voice-led ad, and always under the voice.
- Change only what was asked, keep the file name, keep versions, apply a cross-cutting fix to the whole batch.

## 6. Troubleshooting

Validation issue codes (errors block rendering, warnings do not):
- `schema`: unknown field, wrong type or missing field; `where` gives the path. Check `storyboard_schema`. `Unknown field` means a typo or a field of another object. Every bad value is reported at once, so one validation shows all the fixes: a `shot_type`, `scale`, `emotion` or `role` outside the vocabulary names the field (`segments[3].role`) and lists the allowed values.
- `missing_file`, `path_escape`: file not under the project, or an absolute path. Use relative paths and `library_index` the new files.
- `file_probe`, `source_type`: ffmpeg cannot read the file, or it is an image where a clip is needed (and the reverse).
- `source_duration`: `out` is after the end of the clip. Shorten `out`.
- `segment_in`: negative `in`.
- `overlay_after_end`: an overlay starts after the video ends. You used clip-local time or a wrong sum: recompute the timeline.
- `overlay_timing`: `end` is not greater than `start`.
- `overlay_clamped` (warning): overlay ends after the video, it will be cut.
- `text_overflow` (warning) and "caption overflow" from `caption_preview`: the text is wider than the max width even after shrinking. Cut the line, add a line break, or drop the size; do not accept a size under about 50 px on a main text.
- `bbox_out_of_canvas`: the text falls outside 1080x1920. Change `y`, `anchor` or `size`.
- `font_not_found`, `text_render`: bad `family` or brand font, or an emoji problem. Use a bundled family or remove the field.
- `digital_zoom` (warning): a segment enlarges its source more than 1.25x beyond a plain cover-fit, through `crop`, `zoom.to` or `freeze.zoom`. Pick a shot filmed close instead of cropping.
- `emoji_missing` (warning): a caption holds an emoji with no PNG in the storyboard `emoji` folder, so it would render without it. Add the PNG (named by its codepoints, for example `1f525.png`) or change the emoji.
- `banned_word`: a brand banned word is in a caption. Rewrite it, do not disable the list.
- `product_too_early` (warning): the product appears before the story turns to the solution; open on people living the problem.
- `ref_*` (warnings, only when `reference` is set): `ref_missing` (breakdown not found or invalid, other checks skipped), `ref_pacing` (mean shot above 1.35x the reference), `ref_types` (a shot type the reference uses is neither in a segment `shot_type` nor in `gaps`), `ref_closeups` (under half the reference's close-up share), `ref_people` (fewer than 2 `person_*` subjects when the reference shows 3 or more), `ref_text_rhythm` (fewer written captions than half the reference's text changes), `ref_text_device` (the reference's texts are people speaking, a character quote, and fewer than half as many of your captions look like `<emoji or name> : « ... »`), `ref_unannotated` (under 70% of segments have a `shot_type`), `ref_unannotated_emotion` (under 70% of the `person_*` segments have an `emotion`).
- `emotion_mismatch` (warning): a segment with `role` `problem`, `myth` or `agitation` has the `emotion` `happy`, `satisfied` or `relaxed` (the text complains while the face smiles), or, with a `reference`, a `punch` segment is `neutral`, `relaxed`, `happy` or has no emotion while the reference answers its punches (or questions) with a reaction face (`shocked`, `skeptical`, `frustrated`). Pick a shot with the right face.
- `cut_mid_word` (warning, with `audio.clips`): a cut of the sound (a segment `in` or `out`, or the range of an `audio_from`) falls inside a spoken word of its source. Move it into the pause, or paste the `clean_segments` of `speech_view`. Not raised when the next segment resumes the same source where this one stopped (within one frame): the sound is continuous across the cut.
- `banned_word_spoken` (warning, with `audio.clips`): a kept spoken word is a banned word of the brand (the creator says what the brand may not claim). Cut it out or pick another take; the captions made from the speech do not raise `banned_word` for it.
- `speech_missing` (warning): a clip with sound has no speech index (not indexed, or no transcriber yet), so `cut_mid_word`, `banned_word_spoken` and `speech_captions` cannot see it; run `library_index` with `transcribe=true`. Also raised when `speech_captions` finds no word to show.
- `speech_captions` (error): the overlay needs `audio.clips: true`.
- `speech_corrections`: a warning listing every `corrections` entry of a `speech_captions` overlay with how many times it was applied (0x: never heard), for a human to check against the audio; an error when a correction changes a word too much (similarity under 0.5) or is not one word: run `speech_refine` on the clip instead.
- `caption_on_end_card` (warning): a written, voice or speech caption stays more than 0.2 s on the end card image (the last segment labelled `end_card` when it is an image, or the brand's `cta_image`). End the caption before the card.
- `cta_text_missing` (warning): `brand.yaml` has a CTA wording (`product.cta_text`) and no caption (written, voice or speech) contains it, ignoring case, accents and quotes. Add it as a caption on the end, unless your end card image already shows it (ending on the brand's own CTA image counts as showing it).
- `audio_from` (error): `audio_from` needs `audio.clips: true`, and its source must have an audio stream with enough sound from `in` for the whole segment.
- `cta_image_unused` (warning): `brand.yaml` has a `cta_image` and the last segment is neither that image nor labelled `end_card` with a reason in `gaps` (type `other`).
- `score_*` (warnings, only with `score_check=true`): the pixel-free checks of the creative score (`score_reading_time`, `score_reading_long_line`, `score_product_too_early`, `score_product_never_shown`, `score_cta_missing`, `score_cta_wording`, `score_cta_not_at_end`, `score_safe_zone`); each message ends with its fix. They are the same findings `ad_score` counts, so fixing them before the render raises the score.
- `emphasis_unmatched` (warning): an `emphasis` entry of a written caption matches no word of its lines, so nothing is highlighted (also reported by `caption_preview`). Write the entry as shown (`65,90 €`, a phrase as consecutive words) or mark it with `*...*`.
- `split_layout` (error): a `gap` that leaves a panel under 64 px. `panel_crop` (error): a panel `crop` leaves its source. `split_crop` (warning): a panel keeps under 40% of its source after the cover crop: set its `focus`, pick the other layout or another shot. A split label wider than its panel is a `text_overflow` warning. `split_same_source` (warning): the two panels of a split, or the two sides of a reveal, are one file at overlapping moments, so the difference will not be visible: use real before and after pictures. `reveal_orientation` (warning): the two sides of a reveal are not both portrait, landscape or square. `reveal_after_short` (warning): a reveal leaves under 0.6 s on the after picture. A reveal side shares the errors `source_duration` and `panel_crop` with a split panel.
- `inset_out_of_frame` (error): a video inset leaves the frame. `inset_audio` (error): `audio: true` without `audio.clips`, with a voice-over (`audio.voice`) or another voiced inset or an `audio_from` segment at the same time. `inset_audio_replaces` and `inset_audio_silent` (warnings), `inset_source_short` (warning: the inset's clip ends before its span and holds its last frame).
- `caption_covered_by_inset` (warning): a caption's box meets a video inset while both are on screen. `sticker_out_of_frame` (error) and `sticker_render` (error: the sticker cannot be drawn, for example an emoji without a picture).
- recipe rule ids (`product_shot_floor`, `end_card`, `total_duration`, `caption_time`, `safe_zone`...): read the message, fix the durations, labels or positions. `end_card` needs the LAST segment labelled `end_card`.

Render failed: `job_status` returns `status: "failed"` and an `error` string (ffmpeg command and last stderr lines). Read it, fix the storyboard (usually a bad crop, an unreadable source, or a remove_text box outside the frame) and start a new job. If the detached runner dies, status reports `runner process died`; inspect the adjacent job log before retrying.

QC checks (`qc_run`, `fail` blocks delivery, `warn` needs a decision):
- `color_tags`: output not tagged bt709. Probe the file and re-render, never hand-fix.
- `audio_tail`: audio stops before the end or is silent in the last second. Extend the music, raise volume, or check `from_reference` covers the whole video.
- `overlay_visible`: a caption disappears before its end. Check its `end`, the timeline sum, and that the overlay is not clamped.
- `black_frames`: black intervals. Usually a bad `in`/`out` or an image letterbox; pick other timecodes.
- `frozen_frames`: frames frozen for 1.5 s or more. A static source or a freeze that is too long; shorten it or pick a moving shot.
- `loudness`: outside about -24 to -9 LUFS. Adjust `volume` or `audio.loudness`.
- Also checked: `decode`, `resolution`, `fps`, `pixel_format`, `duration` (against the storyboard), `audio_present`, `audio_duration`, `audio_gaps`.
